Under the hood: DevTools Protocol

Playwright doesn't talk to the browser through WebDriver. It talks through DevTools Protocol — the same channel Chrome DevTools uses. That's why downloads, network interception, console events, and trace recording are first-class APIs here and not in your Selenium suite.

Selenium 4 added a CDP escape hatch — Chrome-only, outside the WebDriver standard.

Plant this early. It pre-empts the "can't Selenium do that?" Q&A. Every feature we see today exists because of this architectural decision. When you see something that looks impossible for a test framework, remember: Playwright is using the same channel as your browser's devtools.

Web-first assertions vs. Thread.sleep

TypeScript

await saveButton.click();

page.waitForResponse()

TypeScript

const resp = await page.waitForResponse(
  '**/api/save',

page.route()

Mock your backend calls

TypeScript

await page.route('**/api/products',
  route => route.fulfill({
    status: 500,
    body: 'Internal Server Error'
  }));
// Also: abort(), continue() with overrides
Java

page.route("**/api/products",
    route -> route.fulfill(
        new Route.FulfillOptions()
            .setStatus(500)
            .setBody("Internal Server Error")));
// Also: abort(), continue() with overrides
Test every backend failure state without touching the backend.
fulfill() returns a canned response. abort() simulates a network failure. continue() with overrides rewrites the request in flight — rewrite URLs, inject headers, swap body fields. Most teams know fulfill and abort. The continue-with-overrides is the sleeper.

routeFromHAR()

Replay tests against a recorded backend

TypeScript

// Record once:
const context = await browser.newContext({
  recordHar: { path: 'fixtures/api.har' }
});
// Replay forever:
await context.routeFromHAR('fixtures/api.har',
  { notFound: 'fallback' });
Java

// Record once:
context = browser.newContext(
    new Browser.NewContextOptions()
        .setRecordHarPath(Paths.get("fixtures/api.har")));
// Replay forever:
context.routeFromHAR(Paths.get("fixtures/api.har"),
    new BrowserContext.RouteFromHAROptions()
        .setNotFound(RouteFromHARNotFound.FALLBACK));
Commit the HAR. Your backend becomes optional for UI tests.
Record real traffic once, commit the HAR to source control, replay it deterministically in CI. Pairs with setOffline for fully hermetic tests. The update:true flag lets you refresh periodically without manual recording.

"Your frontend is the most authoritative documentation your backend has — and Playwright lets you read it at runtime."

Act 3 flips the direction. Instead of isolating the frontend from the backend, we use the browser to reach the backend — borrow its session, its CSRF token, its auth state. Most tools can't do this. Playwright can, because it has a real browser and a real HTTP client in the same process.

Reuse your session across tests

Log in once. Never log in again.

TypeScript

// Global setup — log in, then save:
await context.storageState({ path: 'auth.json' });

// Every test — start already authenticated:
const context = await browser.newContext({
  storageState: 'auth.json'
});
Java

// Global setup — log in, then save:
context.storageState(new BrowserContext.StorageStateOptions()
    .setPath(Paths.get("auth.json")));

// Every test — start already authenticated:
BrowserContext context = browser.newContext(
    new Browser.NewContextOptions()
        .setStorageStatePath(Paths.get("auth.json")));
Log in once per suite run. Every test starts already authenticated.
storageState() saves cookies and localStorage to a file. Load it into any new context and that context is already logged in — no UI login flow, no API call, just the session. Commit auth.json to your test fixtures or regenerate it in CI setup. If your app uses localStorage tokens, this catches those too — not just cookies.

Layer-crossing auth

Browser login → scrape what you need → call the backend directly

TypeScript

// Scrape CSRF and session cookie
const csrf = await page.evaluate(() => document.querySelector('meta[name="csrf-token"]').content);
const session = (await context.cookies()).find(c => c.name === 'session');

// Set CSRF and Session on the api context
const api = await request.newContext({
  baseURL: process.env.BASE_URL,
  extraHTTPHeaders: { 'X-CSRF-Token': csrf, 'Cookie': `session=${session.value}` }
});

// Hit the backend directly — no more UI
const resp = await api.get('/api/account/settings');
expect(resp.status()).toBe(200);
Walk through each step: 1. Real browser login — no mocking, no token injection, actual session 2. page.evaluate() reaches into the live DOM to grab the CSRF token 3. context.storageState() hands the session cookies to APIRequestContext inline — no file needed 4. From here the browser is out of the picture — pure HTTP calls with real auth

Observer patterns

TypeScript

// JS console errors
page.on('console', msg => {
  if (msg.type() === 'error')
    errors.push(msg.text());
});
// Unhandled exceptions
page.on('pageerror', err =>
  failures.push(err.message));
// Failed network requests
page.on('requestfailed', req =>
  networkFailures.push(
    `${req.url()} — ${req.failure()}`));

expect(errors).toHaveLength(0);
Java

// JS console errors
page.onConsoleMessage(msg -> {
    if (msg.type().equals("error"))
        errors.add(msg.text());
});
// Unhandled exceptions
page.onPageError(err ->
    failures.add(err.message()));
// Failed network requests
page.onRequestFailed(req ->
    networkFailures.add(
        req.url() + " — " + req.failure()));

assertThat(errors).isEmpty();
Catches "passing test, silently broken app." Wire once, benefit everywhere.
The problem this solves: a test can pass green while the page has JS errors, failed XHRs, unhandled exceptions — because you never asserted on any of them. Wire these three listeners once in your base class. Surface every signal as part of the failure context automatically. ~90s slot.
